| 2026-08-03 | REQ-CORE-021 (Phase C unit 3, loop-driven): semantic retrieval, Configuration B. Core declares an `EmbeddingProvider` interface and the client supplies one — the no-env-vars rule forces this, and it has the useful side effect of making AC1 testable without a network, since a provider that counts its own calls proves "zero API calls on the second run" directly. Cache entries are keyed by a hash of the *embedded text*, not by symbol ID: a symbol keeps its ID across edits to its body, so a symbol-keyed cache would serve a vector for text that no longer exists — text-keying makes per-symbol content invalidation fall out automatically, dedupes identical text, and puts the model ID in the header so a cache written by another model is discarded rather than merged. Untouched entries are pruned per run (a bug caught by its own test: `touched` initially accumulated across runs sharing a cache object, so `beginRun()` now scopes it). Embedded text draws on the same fields BM25F does so A and B are compared on equal information. Vendor adapter for OpenAI `text-embedding-3` lives in the CLI (`embedding-provider.ts`) with retry on 429/5xx, no retry on 4xx, and response items ordered by their `index` rather than array position, since core matches vectors to inputs positionally. 24 core + 15 CLI tests, none touching the network.
